## Español (ES)

### Comportamiento actual del launcher

> **Nota:** Este documento ha sido generado por IA y revisado posteriormente.

### Propósito

El archivo `main.py` inicia el launcher de la aplicación (`frontend/app_launcher.py`) como un proceso hijo y registra una función de apagado para intentar cerrar ese proceso cuando el programa principal termina normalmente.

### Arranque

- Calcula la carpeta donde está ubicado `main.py` y construye desde ella la ruta a `frontend/app_launcher.py`.
- Usa `sys.executable` para iniciar el launcher con el mismo intérprete de Python que ejecuta `main.py`.
- Guarda el objeto de proceso devuelto por `subprocess.Popen` en la lista `processes`.
- En Windows, inicia el launcher con `CREATE_NEW_PROCESS_GROUP`.
- En otros sistemas, inicia el launcher en una sesión nueva mediante `start_new_session=True`.

Actualmente, la lista `launchers` contiene un único launcher: `app_launcher.py`.

### Apagado

La función `kill_children()` recorre los procesos guardados. Si `process.poll()` indica que un proceso principal ya terminó, lo omite. Para los demás:

- **Windows:** envía `CTRL_BREAK_EVENT` e intenta esperar hasta tres segundos. Si vence el plazo, ejecuta `taskkill` con `/T` y `/F` para intentar forzar el cierre del proceso y de sus descendientes, y después espera al proceso principal.
- **Linux y otros sistemas POSIX:** envía `SIGTERM` al grupo de procesos y espera hasta tres segundos. Si vence el plazo, envía `SIGKILL` al grupo y espera al proceso principal.

La función se registra con `atexit`, por lo que se ejecuta durante el cierre normal del intérprete de Python.

### Alcance y límites actuales

- El cierre ordenado depende de que el proceso o los procesos del grupo respondan a la señal recibida.
- `process.poll()` comprueba el proceso principal, no confirma por sí solo que todos sus descendientes hayan terminado. Si el proceso principal ya terminó, el código omite esa entrada aunque pudiera haber descendientes activos.
- La función solo captura `subprocess.TimeoutExpired`. Otros errores durante el envío de señales o la ejecución de `taskkill` podrían interrumpir la limpieza de los procesos restantes.
- `atexit` no garantiza la limpieza en todos los tipos de terminación: por ejemplo, no se ejecuta si el proceso principal es terminado a la fuerza o sufre un error fatal.
- El launcher inicia actualmente un solo proceso de aplicación; el código permite ampliar la lista de launchers.

## English (EN)

### Current launcher behavior

> **Note:** This document was generated by AI and subsequently reviewed.

### Purpose

The `main.py` file starts the application launcher (`frontend/app_launcher.py`) as a child process and registers a shutdown function that attempts to close that process when the main program exits normally.

### Startup

- It finds the folder containing `main.py` and builds the path from there to `frontend/app_launcher.py`.
- It uses `sys.executable` to start the launcher with the same Python interpreter that is running `main.py`.
- It stores the process object returned by `subprocess.Popen` in the `processes` list.
- On Windows, it starts the launcher with `CREATE_NEW_PROCESS_GROUP`.
- On other systems, it starts the launcher in a new session using `start_new_session=True`.

Currently, the `launchers` list contains one launcher: `app_launcher.py`.

### Shutdown

The `kill_children()` function goes through the stored processes. If `process.poll()` indicates that a main process has already exited, it skips it. For the others:

- **Windows:** it sends `CTRL_BREAK_EVENT` and attempts to wait for up to three seconds. If the timeout expires, it runs `taskkill` with `/T` and `/F` to try to force the process and its descendants to close, then waits for the main process.
- **Linux and other POSIX systems:** it sends `SIGTERM` to the process group and waits for up to three seconds. If the timeout expires, it sends `SIGKILL` to the group and waits for the main process.

The function is registered with `atexit`, so it runs during normal Python interpreter shutdown.

### Current scope and limitations

- Graceful shutdown depends on the process or processes in the group responding to the signal they receive.
- `process.poll()` checks the main process; by itself, it does not confirm that all descendants have exited. If the main process has already exited, the code skips that entry even if descendants might still be running.
- The function only catches `subprocess.TimeoutExpired`. Other errors while sending signals or running `taskkill` could interrupt cleanup of the remaining processes.
- `atexit` does not guarantee cleanup for every kind of termination. For example, it does not run if the main process is forcibly terminated or encounters a fatal error.
- The launcher currently starts one application process; the code can be extended to include more launchers.
